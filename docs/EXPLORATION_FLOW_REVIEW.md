현재 프로토타입은 **내 행성계를 발견하는 첫 장면**은 충분히 매력적이지만, 그 다음 세계로
자연스럽게 건너가는 출구가 약하다. 바이럴 제품이 되려면 우주를 더 크게 만드는 것보다
**화면에 보이는 모든 이웃을 실제 목적지로 만들고, 매 도착마다 다음 선택을 제시하는 것**이 먼저다.

## 실제 확인한 문제

### 1. 보이는 이웃이 목적지가 아니다

`andy6609` 행성계에서 화면에 보이는 `AzureAD` 별을 선택해도 URL과 제목이 바뀌지 않았다.
현재 계정 초상 모드에서는 전역 picking을 막고 대표 행성의 직접 클릭만 허용하기 때문이다.
사용자는 이름이 붙은 천체를 보면 이동 가능하다고 기대하므로, 이는 장식이 아니라 깨진
상호작용 약속처럼 느껴진다.

### 2. 브라우저의 공간 기억을 사용하지 못한다

사용자 이동이 `history.replaceState`로 기록되어 이전 장소가 사라진다. 행성계와 행성 사이를
여행하는 제품에서 뒤로가기는 단순 브라우저 기능이 아니라 직전 장소로 돌아가는 기본 항해다.

### 3. 도착 후 다음 목적지가 없다

확인된 dependency 항로가 없는 저장소에서는 GitHub 링크 외에 탐험을 이어 갈 선택지가 없다.
추천을 위해 가짜 관계를 만들 필요는 없다. 같은 언어, 같은 은하·지역, 가까운 이웃, 작은
행성계 발견처럼 **근거를 설명할 수 있는 후보 세 개**면 충분하다.

### 4. 공유 실패가 조용하다

Clipboard API가 거부될 때 `window.prompt`를 사용하는데, 인앱 브라우저에서는 지원되지 않아
오류가 난다. 임시 textarea 복사를 보조 수단으로 사용하고 성공·실패를 버튼과 `aria-live`로
명확하게 알려야 한다.

### 5. 공유 링크의 첫인상은 아직 약하다

직접 URL 진입에서 목적지가 보이기까지 약 8–10초가 걸렸고, 문서의 목표인 3–5초보다 길었다.
또한 정적 SPA 문서에는 저장소·계정별 Open Graph 카드가 없다. 항해 시간은 클라이언트에서
먼저 줄이고, 동적 OG 이미지는 서버 렌더링 또는 전용 공유 엔드포인트 단계에서 별도로 만든다.

## 구현 순서

### P0-1. 보이는 다른 행성계 클릭

- 계정 초상에서도 현재 계정을 제외한 중심별을 picking한다.
- 마우스와 터치의 최소 선택 반경을 넓힌다.
- 대표 행성 클릭을 먼저 판정하고, 그 바깥에서 다른 계정 별을 판정한다.
- hover 문구는 설명문이 아니라 `선택하면 @계정의 행성계로 이동`처럼 행동을 예고한다.

**합격 조건:** `andy6609` 화면에서 검색창을 쓰지 않고 보이는 다른 계정으로 이동한다.

### P0-2. 브라우저 뒤로가기 복원

- 검색·클릭·추천 등 사용자 이동은 `pushState`로 쌓는다.
- 공유 URL 복원과 `popstate` 이동은 새 기록을 만들지 않는다.
- 쿼리가 없는 주소로 돌아오면 은하 전체 관측 화면을 복원한다.

**합격 조건:** `andy6609 → 다른 계정 → 뒤로가기`가 `andy6609`로 돌아온다.

### P0-3. 매 도착에 다음 목적지 세 개

- 같은 언어, 같은 은하·지역, 작은 행성계 발견을 우선한다.
- 각 후보에 선택 이유를 한 줄로 표시한다.
- dependency가 아닌 후보를 dependency처럼 표현하지 않는다.
- 세 개를 같은 크기의 카드로 만들지 않고, 항해 표식 같은 짧은 목록으로 둔다.

**합격 조건:** 확인된 항로가 없는 저장소에서도 검색 없이 두 번째 계정으로 이동한다.

### P0-4. 공유 회복

- Clipboard API 실패 시 임시 textarea와 `execCommand('copy')`로 한 번 더 시도한다.
- `prompt()` fallback을 제거한다.
- 성공과 실패를 모두 버튼 문구와 `aria-live`로 알린다.

**합격 조건:** 인앱 브라우저에서도 공유 버튼이 오류 없이 결과를 알려 준다.
